# 环境变量

除 `BETTER_AUTH_SECRET` 外都可选。

| 环境 | 放哪里 |
| --- | --- |
| 本地 | `apps/api/.dev.vars` |
| 生产密钥 | 在 `apps/api` 里执行 `bunx wrangler secret put <NAME>` |
| 生产非密钥 | `apps/api/wrangler.jsonc` 的 `vars` |

不要把密钥写进 `wrangler.jsonc`。`GET /api/config` 是公开的，运行时配置里也不要放密钥。

改完 `wrangler.jsonc` 的 binding 后，在 `apps/api` 执行 `bun run cf-typegen` 重新生成类型。

## 认证与邮件

| 变量 | 作用 |
| --- | --- |
| `BETTER_AUTH_SECRET` | 必填 |
| `BETTER_AUTH_URL` | 认证对外的源站。本地社交登录可用 `http://localhost:5173`；开了 MCP OAuth 或在生产环境，用 API 源站。生产回调是 `${BETTER_AUTH_URL}/api/auth/callback/github` 和 `.../google` |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | 同时非空才显示 GitHub 登录 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 同时非空才显示 Google 登录 |
| `RESEND_API_KEY` / `EMAIL_FROM` | 邮箱验证码。两个都配，或都不配。不配时验证码打到 Worker 控制台 |
| `PUBLIC_API_URL` | 写进头像和组织 logo URL 的稳定源站，形如 `${PUBLIC_API_URL}/api/media/<assetId>`。本地用 `http://localhost:8787`，图片请求直接打到 Worker |

新的前端域名要加进 `apps/api/src/index.ts` 的 `trustedOrigins`。

## 对象存储

附件走 S3 协议（SigV4）。换 R2、MinIO 或 OSS 只改变量，不改代码。没配齐时服务能启动，附件接口返回 503。

| 变量 | 作用 | R2 示例 |
| --- | --- | --- |
| `S3_ENDPOINT` | S3 兼容地址 | `https://<accountId>.r2.cloudflarestorage.com` |
| `S3_REGION` | 区域 | `auto` |
| `S3_ACCESS_KEY_ID` | Access Key | R2 API Token |
| `S3_SECRET_ACCESS_KEY` | Secret | R2 API Token |
| `S3_BUCKET` | 桶名 | `my-bucket` |
| `S3_PUBLIC_BASE_URL` | 可选，公开读的自定义域名 | `https://cdn.example.com` |

本地 MinIO 的启动方式见 [本地开发](本地开发.md)。

R2 需要给桶配 CORS，仓库里有 `apps/api/r2-cors.json`：

```sh
wrangler r2 bucket cors set <bucket> --file r2-cors.json
```

文件用 Cloudflare 的 `rules` + `allowed` 格式。浏览器直传必须允许 `PUT`，并放行 `content-type`。上传流程是：先拿预签名 URL，客户端 `PUT` 时带上签名时的 `Content-Type`，再调注册接口。对象 key 由服务端生成，固定为 `orgs/{orgId}/issues/{issueId}/{uuid}.{ext}`。

## 账单

`STRIPE_SECRET_KEY`、`STRIPE_PRICE_ID`、`STRIPE_WEBHOOK_SECRET` 三个一起配。只配一部分会返回 503。

`BILLING_MOCK_MODE=true` 时，没有 Stripe 也能走完升级和降级，适合本地。Webhook 地址是 `<api-url>/api/stripe/webhook`，事件：`checkout.session.completed`、`customer.subscription.updated`、`customer.subscription.deleted`。

## AI 与 MCP

说明见 [AI 与 MCP](AI与MCP.md)。相关变量：

| 变量 | 作用 |
| --- | --- |
| `AI_ENABLED` | `true` 打开应用内助手 |
| `AI_PROVIDER` | `mock`（离线、固定回复）或 `openai-compatible` |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` | 真实模型三个都要。缺任何一个会以 `AI_NOT_CONFIGURED` 失败。兼容 OpenAI、DeepSeek、SiliconFlow、通义、OpenRouter、Ollama、AI Gateway |
| `AI_MODEL_ALLOWLIST` | 可选，逗号分隔。设置后必须包含 `AI_MODEL` |
| `AI_MAX_STEPS` / `AI_MAX_OUTPUT_TOKENS` | 单轮上限 |
| `APP_WEB_URL` | 前端源站，用于 AI 深链和 MCP 登录 / 同意页跳转 |
| `MCP_ENABLED` | `true` 暴露 `POST /mcp` |
| `MCP_RESOURCE` | MCP 受保护资源 URL，也是 OAuth audience，例如 `https://api.example.com/mcp` |
| `MCP_LOGIN_PAGE` / `MCP_CONSENT_PAGE` | 默认 `${APP_WEB_URL}/login` 和 `/consent` |
| `MCP_DCR_ENABLED` | 打开免认证的动态客户端注册。只给本地用 |

## KV

Binding 名是 `KV`。本地由 `wrangler dev` 模拟。部署前 namespace 要先建好，CI 用的 `CLOUDFLARE_API_TOKEN` 需要 Workers KV 权限。

运行时配置在 key `config:global`，进程内缓存 60 秒：

- `GET /api/config` 公开读取
- `PUT /api/admin/config` 由平台管理员写入 `version`、`maintenance`、`announcement`、`features`

组织套餐缓存在 `cache:v1:plan:<orgId>`，标签列表在 `cache:v1:labels:<orgId>`。回退 TTL 1 小时，写入时会主动失效；长 TTL 只是为了少打 KV 写入配额。
