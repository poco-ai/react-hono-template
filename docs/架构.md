# 架构

Bun + Turborepo monorepo。Web 和 API 都跑在 Cloudflare 上：API 是 Worker 脚本，Web 是带 SPA 回退的静态资源。

```text
apps/api
  src/routes.ts          组装路由，导出 AppType（前端类型客户端依赖它）
  src/controllers        HTTP，校验后调 service，包成统一响应
  src/services           业务逻辑。领域错误抛 ApiError
  src/dao                唯一允许写 SQL / Drizzle 的一层
  src/dto                请求和响应类型
  src/v1                 公开 API，Bearer API Key，挂在 /api/v1
  drizzle                迁移。全文搜索的可重放脚本在 drizzle/fts/

apps/web
  src/routes             TanStack Router 文件路由，守卫在 beforeLoad
  src/pages              页面
  src/features/<领域>    data.ts 管请求和缓存，components/ 管界面
  src/i18n               en.ts 是文案源，zh.ts 跟它的类型对齐

packages/shared          Zod schema、套餐限额、错误码、统一响应包
packages/ui              shadcn/ui。添加组件：bunx shadcn@latest add <name> -c apps/web
```

`@workspace/shared` 和 `@workspace/ui` 直接导出 TypeScript 源码，改完即生效。

## API

调用方向只有一条：`controller → service → dao → db`。加一个资源的顺序：表和迁移、dto、dao、service、controller、`src/routes/` 里的路由、挂到 `routes.ts`，再在 `packages/shared` 补 Zod schema。

业务路由在 `/api/orgs/:orgId/*` 下，先过登录，再过组织成员。非成员 404。组织被冻结时，写操作返回 403，读和账单仍可用。owner / admin 才有的写操作走角色校验。

公开 API 复用同一套 dao / service，但在类型客户端的 `AppType` 之外。限流用 Workers Rate Limiting，`wrangler.jsonc` 里的限额要和 `packages/shared` 的 `PLANS` 保持一致。

## Web

`features/<领域>/data.ts` 是该领域唯一的数据入口：query key、请求、mutation、缓存失效放在一起。页面负责表单、弹层、跳转和文案。界面文案走 `useTranslation()`，不要写死在组件里。

列表筛选放在 URL search params 里，用 Zod 校验。`/` 对未登录用户是落地页，登录后进入第一个组织。

前端通过 `hc<AppType>` 拿到 API 的类型。开发时 `VITE_API_URL` 为空，请求走 Vite 的 `/api` 代理；生产构建把 API 地址写进 `VITE_API_URL`。

更细的约定（缓存失效、FTS 触发器、Workers 限制）在 [AGENTS.md](../AGENTS.md)。
