# 自建部署

Cloudflare 仍然是默认路径，步骤在 [部署.md](./部署.md)。这一页是第二条运行时：Bun 进程、PostgreSQL、Redis、S3 兼容对象存储。Web 仍是 Vite 的静态产物，由反向代理托管，前端数据层不用改。

MySQL 目前只是方言槽位。`SQL_DIALECT=mysql` 会在打开数据库之前报错，没有表、迁移或驱动。

## 进程里有什么

`apps/api/src/server.ts` 读取 `apps/api/.env`（不会覆盖已经存在的环境变量），把方言设成 PostgreSQL，然后启动同一个 Hono 应用。

- 数据库：`DATABASE_URL`。时间列仍是毫秒整数，查询不用改成 `timestamptz`。
- 缓存和限流：`REDIS_URL`。读写策略和 KV 是同一份，配置与套餐的 60 秒进程内缓存也是同一份。公开 API 和 AI 的限额来自 `packages/shared` 的 `PLANS`，窗口和 Cloudflare 的 `period` 一样是一分钟。
- Webhook：Redis 列表加延迟重试。消费循环调用现有的投递逻辑，次数和 5 秒间隔与 Queues 的 `max_retries`、`retry_delay` 相同。
- 定时任务：进程内每 15 分钟跑一次现有的清理和循环事项，并用 Redis 锁包住。间隔与 Worker cron 相同。单副本的 Compose 也走这把锁，避免以后多副本跑两遍。进程启动时不会立刻跑。
- 对象存储：沿用 `S3_ENDPOINT` / `S3_REGION` / `S3_BUCKET` / 密钥。region 用 `us-east-1`，不要用 R2 的 `auto`。

全文搜索不共用 DDL。SQLite 继续用 FTS5 和 bm25。PostgreSQL 用 `pg_trgm` 的 GIN 索引：三个字符及以上走三元组匹配，更短的词用 `strpos`。排序按 `updated_at`，没有 bm25。

预签名上传绑定 `Content-Length`。若 API 和浏览器通过不同地址访问同一存储服务，用 `S3_ENDPOINT` 配内部地址，用 `S3_SIGNING_ENDPOINT` 配浏览器地址。不要签完再替换域名。

## 本机直接跑 API

准备 PostgreSQL 16 和 Redis 7，然后：

```sh
cp apps/api/env.server.example apps/api/.env
# 改 BETTER_AUTH_SECRET，并确认 DATABASE_URL / REDIS_URL
cd apps/api
bun install
bun run db:generate:pg   # 仓库里已经有 drizzle-pg 时可以跳过
bun run db:migrate:pg
bun run dev:server
```

`db:migrate:pg` 会执行 `drizzle-pg/` 里的迁移，再跑 `drizzle-pg/fts/search_trgm.sql`（幂等，可重复执行）。模板只带一条 PostgreSQL 基线（`drizzle-pg/20261124084746_init/`）；从旧模板部署过、库里已有数据的实例要先清空 schema，见[部署 · 从旧模板升级](部署.md#从旧模板升级)。API 默认听 `0.0.0.0:8787`。

在另一个终端从仓库根目录执行 `bun run --cwd apps/web dev`，打开 `http://localhost:5173`。Vite 默认就把 `/api/` 转到 `:8787`；不要同时用根目录的 `bun run dev` 启动占用同一端口的 Wrangler。本机如果启用 MCP OAuth，请将认证源站和 MCP 公开 URL 指向能服务 `/mcp` 和 `/.well-known/*` 的 API，而不是只代理 `/api/` 的 Vite。

## Docker Compose

仓库根目录的 `docker-compose.yml` 包含 PostgreSQL、Redis、rustfs、API 和 Caddy。Caddy 把 `/api`、`/mcp`、`/.well-known` 转到 API，其余文件走 `apps/web/dist`，并做 SPA 回退。因此生产构建可以不设 `VITE_API_URL`，请求仍是同源的 `/api`。

```sh
bun run --cwd apps/web build
docker compose up -d --build --wait
```

浏览器打开 `http://localhost:8080`。建桶失败时 API 不会启动；建桶成功后，API 容器先迁移再监听。API 通过 `rustfs:9000` 核验对象，浏览器拿到 `localhost:9000` 的直传 URL。Compose 通过 `RUSTFS_CORS_ALLOWED_ORIGINS` 只允许本地 Web 源站跨域访问 RustFS。

这份 Compose 用于本机试跑，端口仅绑定到回环地址，并含示例密钥和模拟计费。对外部署前应移除示例密钥、关闭模拟计费、配置 HTTPS 和自己的认证源站；不要直接把示例端口暴露到公网。

可以使用已有的 S3 兼容存储。替换 API 的 `S3_*` 变量，并自行建桶和配置 CORS；不必启动 Compose 中的 `rustfs` 和 `rustfs-init`。

## 变量

完整清单在 `apps/api/env.server.example`。必填：

| 变量 | 作用 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接串 |
| `REDIS_URL` | 缓存、限流、webhook 队列、定时锁 |
| `BETTER_AUTH_SECRET` | 会话签名 |
| `S3_ENDPOINT` / `S3_REGION` / `S3_BUCKET` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | 启用附件所需；未配置存储不影响 API 启动 |

`TRUSTED_ORIGINS` 是逗号分隔的来源。不设时仍是 `http://localhost:5173` 和现有的生产 Web 域名。Compose 把它设成 Caddy 的 `http://localhost:8080`，并保留 Vite 的来源。

`BILLING_MOCK_MODE=true` 时账单走本地确认。Stripe、Resend、AI 的规则和 Cloudflare 一样：一组变量要么齐，要么都不设。

`SQL_DIALECT` 只接受 `postgres`。不设也是 PostgreSQL。`sqlite` 留在 Cloudflare Worker 入口，Bun 进程里会拒绝。

## 冒烟

不带环境变量运行测试时，PostgreSQL/Redis 冒烟会跳过。CI 提供一次性的 PostgreSQL 16 和 Redis 7 容器，覆盖注册登录、创建 Issue、搜索、Redis 限流，以及 Webhook 入队和消费。测试会向两种服务写数据，本地也请只接一次性实例。

```sh
docker compose up -d --wait postgres redis
DATABASE_URL=postgres://app:app@127.0.0.1:5432/app \
REDIS_URL=redis://127.0.0.1:6379 \
bun test apps/api/tests/postgres-smoke.test.ts
```

没有这两项环境变量时，该测试会跳过。
