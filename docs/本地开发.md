# 本地开发

最小启动见根目录 [README](../README.md)。下面是按需打开的能力。密钥写在 `apps/api/.dev.vars`（从 `.dev.vars.example` 复制），这个文件不要提交。

只配 `BETTER_AUTH_SECRET` 时：

- 账单走模拟模式（`BILLING_MOCK_MODE=true`）
- 附件接口返回 503
- 邮箱验证码和重置密码链接打印在 `wrangler dev` 的控制台

## 附件（MinIO）

上传使用预签名 URL，浏览器把文件直接 `PUT` 到 `S3_ENDPOINT`。本地用 MinIO：

```sh
docker run -d --name minio -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio server /data --console-address ":9001"
```

在 <http://localhost:9001> 建一个桶（例如 `test-bucket`），或：

```sh
docker run --rm --network host minio/mc sh -c \
  "mc alias set local http://localhost:9000 minioadmin minioadmin && mc mb local/test-bucket"
```

然后在 `.dev.vars` 里写上：

```sh
S3_ENDPOINT=http://localhost:9000
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=minioadmin
S3_SECRET_ACCESS_KEY=minioadmin
S3_BUCKET=test-bucket
```

MinIO 默认允许浏览器跨域 `PUT`。生产用 R2 时要单独配 CORS，见 [环境变量](环境变量.md)。

## 邮件

邮箱验证码登录走 [Resend](https://resend.com)，验证码 6 位、5 分钟有效，只发给已经注册的账号。`RESEND_API_KEY` 和 `EMAIL_FROM` 要一起配，`EMAIL_FROM` 必须是已验证的发件人，例如 `Acme <no-reply@example.com>`。

重置密码目前没有默认的发信实现，链接同样打在 Worker 控制台。上线前要接到真实邮件，见 [生产说明](生产说明.md)。

## 社交登录

GitHub、Google 各自要同时有 client id 和 secret，缺一个则对应按钮不显示。

本地把 `BETTER_AUTH_URL` 设为 `http://localhost:5173`，回调回到 Vite，再由 `/api` 代理到 Worker：

- `http://localhost:5173/api/auth/callback/github`
- `http://localhost:5173/api/auth/callback/google`

如果同时开了 MCP OAuth，改用 API 源站 `http://localhost:8787`，让 issuer、JWKS 和 MCP resource 的 audience 一致。这时社交登录的回调也指向 API 源站。

## AI

`.dev.vars` 里设置 `AI_ENABLED=true`，`AI_PROVIDER` 保持 `mock`，不需要 API Key。模拟提供者会返回固定回复，对话、配额和工具卡片都能在本地看。接真实模型见 [AI 与 MCP](AI与MCP.md)。
