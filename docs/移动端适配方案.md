# 移动端适配方案（已定稿）

> 目标：在 375px 级别的手机屏幕上获得真正的移动端体验（触控友好、单手可达、无横向溢出），同时保证桌面端体验零回退。不引入原生 App，纯响应式 Web。

**已确认的决策：**

1. ✅ 增加移动端底部 Tab 栏（Inbox / 我的 / 项目 / AI）
2. ✅ Roadmap 移动端采用堆叠列表视图（<768px）
3. ✅ P0–P3 四期 + P4 验收全部纳入本次实施（约 8–13 人日）

### 缺口（按严重程度排序）

1. **项目页头部工具栏溢出（核心页面！）** — `pages/project-issues.tsx` 头部 action 区（L510 附近）是不换行的 `flex`，塞了 ~9 个控件：收藏、项目动态、周期、循环任务、列表工具栏、视图切换、列表/看板切换、导入导出、新建 issue，合计约 800px 宽，375px 下直接溢出裁切。
2. **Issue 列表表格不可用** — `issue-list-row.tsx` 中 status（w-28）/priority（w-24）/assignee（w-28）/updatedAt（w-28）永远可见，行最小宽度约 600px，靠横向滚动苟活；标题列被挤压。且勾选列 `hidden md:table-cell`，**手机上无法多选，批量操作完全不可达**。
3. **BulkActionBar 在手机上是无效功能**（依赖上面的勾选）且自身在 375px 会堆成很高的柱子。
4. **Roadmap 是纯桌面页** — `pages/roadmap.tsx` 用 `min-w-[54rem]` + `14rem minmax(40rem,1fr)` 网格，只有横向滚动。
5. **Issue 详情属性面板在移动端被压到页面最底部** — `flex-col` 堆叠后，要滚过描述、子任务、关联、评论、附件、动态才能改状态/负责人，移动端高频操作成本极高。
6. **二级表格无列隐藏**：`admin-orgs.tsx`（7 列）、`org-settings/webhooks.tsx`（5 列）及 webhook deliveries 弹窗，仅靠横滑。
7. **my-issues 表格**：`table-fixed` + 常驻 number/priority/avatar 列，375px 下标题只剩 ~9rem。
8. **新建 issue 弹窗**：居中 Dialog 在手机上体验差（表单长、底部按钮远），且 `create-issue-dialog.tsx` L346 固定 `grid-cols-2` 两列表单在窄屏过挤。
9. **触控细节**：多处 `size-7`（28px）图标按钮低于 40px 触达标准；`text-sm`（14px）输入框在 iOS 聚焦会触发页面缩放；`group-hover` 才出现的编辑铅笔在触屏上不可见；固定底栏无 safe-area 处理。
10. **导航模型**：目前移动端只有「汉堡 → 全量侧边栏」一条路，高频目的地（Inbox、My Issues）需要 2 次点击且不可见——没有移动端惯用的底部导航。

## 二、产品设计方案

### 2.1 目标与非目标

**目标（移动端核心用户任务，按优先级）：**
1. 查看和处理 Inbox 通知
2. 浏览我的 Issue / 项目 Issue 列表，快速筛选
3. 查看 Issue 详情，修改状态/优先级/负责人
4. 快速新建 Issue
5. 搜索（命令面板）
6. AI 对话（已有基础）

**非目标（优雅降级即可）：** Roadmap 完整时间轴、管理后台、组织设置、Webhook 管理——保证可用、不溢出，不做深度优化。

**断点约定：** 统一以 `md (768px)` 为移动端/桌面端分界（与现有移动顶栏 `md:hidden` 一致）。现有筛选 Sheet 的 640px 断点统一迁移到 768px，消除 640–768 的中间态（小平板竖屏获得移动 UI 是更好的体验）。

### 2.2 导航模型（关键决策：底部 Tab 栏）

移动端（<768px）增加**底部 Tab 栏**（4 项，`md:hidden`）：

```
[ Inbox① ]  [ 我的 ]  [ 项目 ]  [ AI ]
```

- Inbox 带未读数 Badge（复用 `unreadCountQuery`，react-query 自动去重）
- 「项目」为默认落地项
- 顶栏简化为：汉堡（全量导航：Roadmap/分诊/动态/设置等低频项仍在侧边栏 Sheet）+ 组织名 + 搜索 + 主题切换；AI 按钮从顶栏移除（进了 Tab 栏）
- 内容区底部预留 `pb-14 + safe-area`

理由：汉堡侧边栏保留全量导航的可达性，底部 Tab 覆盖 80% 的高频移动场景并让它们「可见 + 1 击可达」。这是本次改造中体感提升最大的一项。

### 2.3 核心页面交互规格

**① 项目 Issue 页（P0）**
- 头部拆两行：标题行（名称 + key + 描述 + meta，现状保留）+ 操作行
- 操作行（<md）：`[列表/看板 图标切换] [筛选 按钮(含计数)] [⋯ 更多菜单] [新建 issue（主按钮）]`
- 「更多」DropdownMenu 收纳：项目动态、周期、循环任务、导入导出、视图切换、分组/密度/列设置
- 桌面端（≥md）保持现状不动
- 筛选 Sheet 断点从 640 统一到 768

**② Issue 列表：移动端卡片模式（P0）**
- <md 时不渲染表格，渲染卡片列表（新组件 `IssueCardList`，与 `IssueList` 同层，桌面继续用表格）
- 卡片结构：

```
● 进行中  PROJ-123                    ⚠ 高
标题（最多 2 行）
[标签…] [头像] · 更新于 2 小时前
```

- 分组标题（groupBy）继续渲染；分页保留
- **选择模式**：操作行加「选择」按钮，激活后卡片左侧出现勾选框，选中后底部弹出批量操作 Sheet（替代现有悬浮 pill）
- 列偏好（列显隐/密度）设置在移动端隐藏（无意义）

**③ Issue 详情（P0）**
- <md 在标题/时间线下方加一条**属性摘要条**：`[状态 chip][优先级 chip][负责人 chip]`，点击弹出**底部 Sheet（max-h-85svh）**，内容直接复用现有 `IssuePropertiesPanel`
- 桌面端右侧 `aside` 布局不变；面板组件只渲染一份（用容器切换挂载位置，避免状态分叉）
- 面包屑行的收藏/订阅/上下条按钮保持图标化，触达尺寸提升到 ≥40px

**④ 新建 Issue 弹窗（P0）**
- <md 升级为全屏 Sheet 风格：`max-md:inset-0 max-md:h-svh max-md:max-w-full max-md:rounded-none`，内部滚动、底部吸附操作按钮、safe-area 内边距
- 表单 `grid-cols-2` → `grid-cols-1 sm:grid-cols-2`

**⑤ Roadmap（P1）**
- <md 切换为**堆叠列表视图**：按项目分节，项目头 + 该项目各周期的竖排卡片（进度条 + 日期区间 + issue 计数），数据完全复用 `features/roadmap/data.ts`
- ≥md 保留 54rem 时间轴

**⑥ 二级表格（P1）**
- `admin-orgs` / `webhooks` / deliveries：按列加 `hidden sm:table-cell` / `hidden md:table-cell` 分层隐藏，操作列常驻
- my-issues：直接复用 `IssueCardList`（与项目列表体验统一）
- triage：行内 accept/decline 按钮在 <md 收进行尾 `⋯` 菜单；全选/批量行允许换行

### 2.4 触控与细节规范（贯穿所有 Phase）

| 项 | 规范 |
| --- | --- |
| 触达目标 | 图标按钮 ≥ 40px：密集处的 `size-7` 加 `max-md:size-9`/`max-md:size-10` |
| 输入框字号 | 全局 CSS 一条规则：`@media (max-width: 767px)` 下 `input/textarea/select { font-size: 16px }`，避免 iOS 聚焦缩放 |
| hover 才可见的操作 | 改为触屏常显：`md:opacity-0 md:group-hover:opacity-50`（如 issue 标题的编辑铅笔） |
| safe area | viewport 加 `viewport-fit=cover`；底部 Tab 栏、批量 Sheet、AI composer 加 `pb-[env(safe-area-inset-bottom)]` |
| 滚动容器 | 统一 `-webkit-overflow-scrolling: touch`（现代 iOS 默认，检查即可）；横向滚动区（看板）已有渐隐提示，保留 |
| 键盘快捷键 | 快捷键提示文案在触屏环境隐藏（`hidden md:inline`） |

## 三、技术方案

### 3.1 实现策略

- **CSS 优先**：能用 Tailwind 响应式前缀（`max-md:` / `md:`）解决的绝不用 JS
- **JS 分叉仅用于组件树切换**：表格 vs 卡片列表、时间轴 vs 堆叠列表（避免双份 DOM 渲染 50 行数据），统一用现有 `useMediaQuery` hook，断点写 `(max-width: 767px)`（与 `md:hidden` 语义一致）
- **零后端改动、零数据层改动**：全部在 UI 层（pages / components / features 的 components 目录），不触碰 `features/*/data.ts` 的请求与缓存策略，天然符合 `architecture.test.ts` 约束
- **零新依赖**：底部 Tab 栏、卡片列表、堆叠 Roadmap 均用现有 shadcn 原语（`Button`/`Sheet`/`DropdownMenu`/`Badge`）+ 普通元素实现
- **i18n**：所有新增文案进 `src/i18n/locales/en.ts`（源）+ `zh.ts`（同步），不硬编码

### 3.3 验收标准（Definition of Done）

- 320–430px 宽度下核心流程全部可完成、无横向溢出（看板的横向滚动属预期）：看列表→筛选→看详情→改状态/负责人→评论→新建 issue→Inbox 处理
- 新建 issue 全局 ≤2 击（Tab 栏/项目页可达）；改状态 ≤3 击
- 768px+ 桌面端 DOM 结构与现状等价（工具栏收纳仅影响 <md），无视觉回退
- `bun run lint` / `typecheck` / `test` 全绿；en/zh 文案齐备

## 六、风险与对策

| 风险 | 对策 |

## 七、明确不做（本期）

- 原生 App / PWA 安装提示（可作后续：Vite PWA 插件 + manifest，接口层零改动）
- 下拉刷新（TanStack Query 的 `refetchOnWindowFocus` + 手动重试按钮已覆盖大部分场景；如需再加轻量 `usePullToRefresh`）
- 手势操作（卡片滑动切状态/长按多选）——成本高、与现有交互模型差异大，先观察卡片模式的使用情况
- Roadmap 移动端完整时间轴（堆叠列表已满足查看需求）
