# 部署

API 和 Web 都部署到 Cloudflare Workers。推到 `main` 且路径命中时，GitHub Actions 会自动部署。仓库密钥需要 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID`。

两条部署 workflow 都先跑可复用的 `quality`（安装依赖、lint、类型检查、测试），通过后才部署。Pull request 也会跑这套检查。Bun 版本读根目录 `package.json`。

手动部署：进入 `apps/api` 或 `apps/web` 后执行 `bun run deploy`。Web 构建时用 `VITE_API_URL` 指向 API。当前示例：

- Web <https://react-hono-web.poco-ai.workers.dev>
- API <https://react-hono-api.poco-ai.workers.dev>

Worker 改名时，这几个地址、`trustedOrigins` 和 web workflow 里的 `VITE_API_URL` 一起改。

## 第一次上线

1. 创建 D1，把 `database_id` 写进 `apps/api/wrangler.jsonc`。创建 KV：`wrangler kv namespace create react-hono-kv --binding KV --update-config`。在 `apps/api` 执行 `bun run db:migrate:remote`。
2. 写入密钥（至少 `BETTER_AUTH_SECRET`）。按需加上 `BETTER_AUTH_URL`、GitHub / Google、S3、Stripe。生产环境的 `BETTER_AUTH_URL` 用 API 源站。把 Web 域名加进 `apps/api/src/index.ts` 的 `trustedOrigins`。
3. 创建队列，再部署带消费者的 Worker：`wrangler queues create react-hono-webhooks`。
4. Stripe：建一个订阅价格，配齐三个密钥，Webhook 指到 `<api-url>/api/stripe/webhook`。事件见 [环境变量](环境变量.md)。

远程 D1 的 drizzle-kit 凭证放在 `apps/api/.env`（`CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_DATABASE_ID`、`CLOUDFLARE_D1_TOKEN`），只给 `db:migrate:remote` / `db:push` 用。不要随手 `db:push`，它会跳过全文搜索触发器的恢复步骤。

## 发布前

API 有 schema 变更时，先迁生产库，再推代码。新 Worker 如果依赖新列或新触发器，打到旧库上会直接失败。

```sh
cd apps/api
bunx wrangler d1 migrations apply react-hono-db --remote
```

确认全文搜索的六个触发器还在。D1 重建 `issues` 或 `comments` 时会静默丢掉触发器，搜索就会返回过期或空的结果：

```sh
bunx wrangler d1 execute react-hono-db --remote --command \
  "select name from sqlite_master where type='trigger' and name like '%_search_a%' order by name"
```

应看到 `comment_search_ad`、`comment_search_ai`、`comment_search_au`、`issue_search_ad`、`issue_search_ai`、`issue_search_au`。

这次迁移如果重建过这两张表，把触发器和索引装回去：

```sh
bunx wrangler d1 execute react-hono-db --remote --file=drizzle/fts/search_fts.sql
```

`apps/api/tests/search*.test.ts` 会在本地检查同样的六个触发器，部署前跑一遍 `bun run test`。然后再推 `main`，等 `quality` 通过。
